# 书架移除：由用户选择是否删除文件（1.0.49）

实现日期：2026-10-17　　交付物：`视频下载器-1.0.49.apk`

## 一、需求

原实现「移除只删索引、绝不碰文件」，用户无法在应用内清理已下载内容。
现改为**由用户自己选择**，同时保留防误删护栏。

## 二、交互

点书架条目上的删除图标 → 弹出选择框：

```
移除《标题》
  移除后这本漫画不会再出现在书架里。
  你可以选择是否同时删除已下载的 1 个压缩包 / N 张图片：
  · 仅移除书架 —— 文件保留，以后还能从下载目录找回
  · 移除并删文件 —— 永久删除，无法恢复

  [移除并删文件]  [取消]         [仅移除书架]
```

选「移除并删文件」**不直接执行**，而是切到二次确认：

```
确认删除文件？
  将永久删除这本书的 1 个压缩包，无法恢复。
  其它漫画的文件、以及下载目录里的其它内容都不会被删除。
  阅读记录会一并移除。

  [返回]                        [永久删除]
```

设计取舍：
- 「仅移除书架」是默认且可逆的出口，放主按钮位；
- 「移除并删文件」用 error 色，且必须再过一次确认 —— 连点两下删不掉东西；
- 两种选择都会清掉**阅读缓存**（应用自己的临时目录，可重建，与用户资产无关）。

## 三、删除护栏（`MangaDeleter`）

不可逆操作按「宁可少删、绝不误删」实现：

| 护栏 | 说明 |
|---|---|
| 白名单 | 只删记录里列出的 URI（下载当时的真实产物），不推断路径、不按名字匹配、不扫目录 |
| 不递归 | `file://` 指向目录时**跳过并报告**，绝不用 `deleteRecursively` |
| 条目上限 | 单本超过 5000 个目标视为记录损坏，整体拒绝 |
| 失败只报告 | 权限/占用失败不重试、不绕过，把「哪些没删掉」交回界面 |

删除结果会如实回报：`已删除 3 个文件，释放 12.4 MB`／`跳过 1 个（不像可删文件）`／`1 个删除失败`。

## 四、顺带修掉的真实缺陷

**中文路径下 `file://` URI 解析错误**（`MangaFiles.fileOf`）。

原实现走 `android.net.Uri.parse(uri).path`，不解码百分号：

```
File(".../Download/视频下载器/本子.zip").toURI()
  → file:///.../Download/%E8%A7%86%E9%A2%91.../%E6%9C%AC%E5%AD%90.zip
  原实现拿到的是字面量含 %E8%A7%86 的路径 → File 不存在 → 删除静默失败
```

下载目录默认就叫「视频下载器」，所以这条路径实际必然被踩到。现已改为纯字符串解析 + `URLDecoder` 解码，
并顺带让 JVM 单测可覆盖（`Uri` 在单测里是桩）。

覆盖的关键场景：
- 压缩包只产生 1 个删除目标、散图去重后逐个删除；
- 兼容只有 `uri` 没有 `uris` 的旧记录；
- 目录一律跳过（测试里真的建了目录，断言递归不被执行）；
- 只删自己那本，无关文件原样保留；
- 中文/空格路径的 URI 编解码。
