# 禁漫多章本子「解析 50 页、下载 25 页」修复（1.0.48）

修复日期：2026-10-17　　交付物：`视频下载器-1.0.48.apk`

## 一、实测根因

用真实接口（本机可直连禁漫 API）拉本子 **350234**，数据如下：

```
/album?id=350234        → total_photos = 50，series = 2 章
                          series[0] = {id: 350234, name: "",  sort: 1}
                          series[1] = {id: 350235, name: "名", sort: 2}
/chapter?id=350234      → images = 25 张（00001.webp …）
/chapter?id=350235      → images = 25 张（00001.webp …）
两章合计 = 50，与 total_photos 一致
/album_download_2/350234（未登录） → {"status":"0","msg":"請先登入"}
```

结论：**`total_photos` 是各章页数之和**。首页写「50 页」指的是两章共 50 页，
而实际只下到 25 页，等于**只处理了第一章**。

## 二、两条下载路径的问题

### A. 官方整本打包（`/album_download_2`）—— 主要风险

该接口按**本子 id** 打包，而在多章本子里本子 id 恰好等于**首章 id**。
旧代码拿到包后只检查「里面有没有图片」（`countImageEntries > 0`），
**完全不校验覆盖范围**，于是第一章的 25 张被当作整本，静默完成。
未登录时该接口不可用会自动回退逐张，所以这个缺陷只在**登录后**触发 ——
这也解释了为什么它不容易被早期测试发现。

修法（`JmPackCheck`）：先逐章拉目录算出 `expected`，官方包必须满足
`actual >= expected` 才采信，否则丢弃并回退逐张下载。

### B. 逐张下载 —— 次要风险

某章 `images` 为空时旧代码是 `continue`，整章静默消失（同样无提示）。
现改为：记录告警 + 在任务备注里点出是哪几章；只有**全部章节都空**时才失败。

## 三、附带修掉的「看不出少了」问题

即使以后再有少页，用户也不该翻到最后一页才发现：

- `JmReconcile`：下载完成后把「预期页数」与「实际张数」对账，不一致直接写进任务备注
  （例：`实际只下到 25 张，比预期的 50 张少 25 张（可能有章节被限制或未取到）`）。
- `JmPageCountText`：多章本子首页改显示 `2 章 · 共 50 页`、下载前提示
  `共约 50 页（各章合计）`，避免把合计误读成单章页数。
