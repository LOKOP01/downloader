# Windows 1.8.10.41：下载路径报错定位、WebP 合并磁盘限额修正与客户端健壮性

## 本次更新

### 下载失败不再只报一句 Permission denied

Windows 上「父目录建不出来」「目标位置被同名目录占用」「目录真的不可写」抛出的都是
`PermissionError: [Errno 13]`，以前用户只能看到一句含义模糊的报错，改权限、换目录都不解决问题。
现在按成因分开报出**可操作**的原因：

- 新增落点预检：归一化路径后校验父目录，并逐个检查 `.part`/`.vpart`/`.apart` 等全部临时落点是否被同名**文件夹**占用。用户报错那次最终文件还不存在，占用发生在 `.part` 位置，只查目标文件会漏掉。
- 分段下载前确认临时文件能真正创建，把「路径/权限问题」与「写入中途失败」区分开：前者换地址重试毫无意义，不再白跑全部候选地址。
- 抖音直链是限时签名，按 `l=` 签发时刻判断是否过期，过期直接提示重新解析，不再跑完所有镜像才失败。

### WebP 合并改为按实际落盘字节限额

PNG 会压缩，旧实现用「未压缩像素数 × 总帧数」预估磁盘占用，会误判：小图多帧的正常合并可能被提前拒绝。
现改为只给下一帧预留保守空间，总量按**实际落盘字节**逐帧限制 2 GiB，并逐帧检查剩余磁盘空间，空间不足时给出可操作原因并清理临时帧。

### 其他修复

- 重试与批量重试跟随用户**当前**下载目录。此前沿用任务创建时的旧路径，表现为「改了下载目录还是下到老地方」。
- 「打开所在文件夹」在目录不存在时给出明确提示，而不是点了没反应。
- 输出目录选择改用 Qt 自绘对话框，避免受限启动环境下原生 Shell 选择器不显示；修复拖放事件在列表/输入框子控件上失效。
- 启动外部程序时隔离 DLL 搜索路径，避免继承程序自身的依赖目录导致 shell 程序加载到错误 DLL。

## 使用与升级

本次附件为**文件夹便携版 ZIP**，无需安装。

1. 解压整个 `VideoDownloader-1.8.10.41` 文件夹到可写位置。
2. 双击文件夹中的「视频下载器.exe」。必须保留同目录的 `_internal` 文件夹，不能只复制 EXE，也不要在压缩包内直接运行。
3. 升级旧版本前先关闭程序，只替换 EXE 与 `_internal`，保留自己的 config.json、edge_profile*、manga_library.json 等个人文件。
4. 运行期临时文件放在程序旁的 `.runtime-temp`，只影响本程序及子进程，不修改 Windows 全局环境变量。

附件仅包含程序与运行依赖，**不含**本机 Cookie、浏览器登录态、个人配置、书架或下载内容。可用 `SHA256SUMS.txt` 校验。

## 已知边界

- 保存目录访问权限、账号权限与网络风控仍以 Windows 与服务端实际允许范围为准；程序无法绕过系统权限。
- 若目录被安全软件或沙箱工具施加了完整性级别限制，程序同样无法写入，此时请改用可写目录。
